- BIXTOK LIVE: LiveKit VP8 (adaptiveStream off: video is bound manually) with P2P fallback in src/lib/bixtok-rtc.ts; chat broadcast+db+polling de-duped by id. Official hosts via bixtok_is_official (Owner 1 + bixtok_official_hosts). PK score is display-only from gift rows; replays are host-recorded parts under the media limit.
- BIX CALL closed-app alerts: messaging-only worker public/bix-push-sw.js (no page caching) + VAPID web push sent by the authenticated sender via notifyBixPush, which re-verifies the message/call row — keeps push Worker-compatible and unforgeable.
- BIX CALL phases: callee device acks via bix_call_ring (sets rang_at) so callers show Memanggil → Berdering → offline (no ack in 25 s); delivered chat ticks come from bix_chat_delivered polled by the global call host — keeps receipts honest without realtime channels.
- Member photo/status/story: profile photo + status live on profiles and are written only via bix_profile_set_* RPCs; stories (bix_stories, 24h, max 10) are readable only through bix_story_can_view (self, chat contacts, network up/downline, mutual follows) in both RPCs and the bix-stories storage policy — one visibility rule for rows and files.
- BIX CALL controls: WA-style 6-button grid; audio route from pickRoute in bix-call-route.ts. Voice calls never request the camera (video button locked) so no browser camera indicator appears; only video calls toggle the camera in-room.
- P2P desk: real stats/merchant tags come only from the bix_p2p_market_pulse RPC; Express takes one best counter-offer atomically via bix_p2p_take. The demo pool (p2p-demo-pool.ts) is a clock-seeded client simulation that may share the live feed and HUD totals only with a visible AMM POOL tag and a simulation footnote and never touches balances — so members can always tell real fills from simulated ones.
- Deposit wallet rotation: several enabled wallets on one network+asset+mode collapse to one stable wallet per member (stickyRotation by user id), so members see a single USDT option. P2P Official Desk fleet (p2p-fleet.ts) is a deterministic, labeled Owner-1 liquidity list; BIX is credited via bix_allocations only after on-chain TxID verification, one credit per TxID via bix_fleet_orders.
- BIX CALL GROUP: education groups (bix_groups/members/messages, member-only RLS, join by invite code via bix_group_join); Live Class reuses bix_call_rooms + MeetingStage with the room code stored on the group.
- BIXGO bookings: members insert pending requests into bixgo_bookings (RLS own rows); only Owner 1 (bix_is_owner1) reads all and dispatches — requests only, no payment captured. City pricing (mult + minimum) lives in the bixgo setting via cityFare.
- BIXGO driver licenses: members apply (pending) in bixgo_driver_licenses; Owner 1 approves; only approved drivers toggle online via bixgo_driver_set_online and read bookings assigned by driver_user_id. Tiers come from active stakes (bixgo-tier.ts) — no license fee or fare is captured in-app.
- BIXGO regions: launch cities (all ID provinces + MY states) live in bixgo-regions.ts and generate default franchises/city pricing; BIXGO prices BIX at its own 0.50 USD reference (BIX_REF_USD) separate from the market reference.
